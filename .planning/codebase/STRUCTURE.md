## Directory Purposes

**src/:**
- Purpose: All application source code (plugin logic, UI components, services, utilities)
- Contains: TypeScript, TSX (Preact), type definitions
- Key files: `main.ts` (plugin entry), `ui.tsx` (UI entry), `types.ts` (contracts)

**src/components/:**
- Purpose: Preact UI components organized by responsibility
- Contains: React-like JSX components with hooks, styled inline
- Key files: `App.tsx` (orchestrator), `ComponentRow.tsx` (most complex, handles edit state), `ComponentList.tsx` (grouping/pagination)

**src/services/:**
- Purpose: External integrations and business logic (AI providers, validation)
- Contains: Async functions, API call logic, error handling per provider
- Key files: `ai.ts` (prompt building, provider routing), `validation.ts` (API key verification)

**src/hooks/:**
- Purpose: Reusable UI logic extracted from components
- Contains: Custom hooks with browser event listeners and state management
- Key files: `useKeyboardShortcuts.ts` (global shortcut handling with platform detection)

**src/utils/:**
- Purpose: Pure utility functions for data transformation and formatting
- Contains: Stateless helpers, no component/hook dependencies
- Key files: `export.ts` (CSV/JSON conversion), `text.ts` (validation/normalization)

**build/:**
- Purpose: Generated compiled output from create-figma-plugin toolchain
- Contains: Minified JavaScript bundles for main thread and UI
- Generated: `npm run build` or `npm run watch`
- Committed: No (git-ignored)

## Key File Locations

**Entry Points:**

- `src/main.ts`: Plugin initialization. Exports `currentPage()` and `allPages()` handlers called by Figma menu.
- `src/ui.tsx`: UI initialization. Default export is Preact render of App component wrapped with create-figma-plugin UI utilities.

**Configuration:**

- `manifest.json`: Generated at build time. Defines plugin ID, name, menu items, entry point handlers.
- `tsconfig.json`: Extends @create-figma-plugin/tsconfig. Includes src/**/*.ts(x), excludes tests.
- `package.json`: Dependencies (preact, create-figma-plugin, vitest), build scripts.
- `vitest.config.ts`: Test runner config. Minimal setup.

**Core Logic:**

- `src/components/App.tsx`: Orchestrates all state (components, settings, search, generation progress). Coordinates between Header, ComponentList, and modals. Owns emit/on subscriptions.
- `src/main.ts`: Figma API access, component discovery via `findAllWithCriteria`, event handlers for apply/select/export.
- `src/services/ai.ts`: `generateDescription()` dispatcher and prompt templating. Provider-specific handlers for ChatGPT, Claude, Gemini.

**Testing:**

- `src/**/*.test.ts`: Colocated test files adjacent to source (e.g., `ai.test.ts` next to `ai.ts`).
- Tests written in Vitest with standard expect() assertions.
- No test utilities or factories; each test file is self-contained.

## Naming Conventions

**Files:**

- Components: PascalCase (e.g., `ComponentRow.tsx`, `SettingsModal.tsx`)
- Services/Utils: camelCase (e.g., `ai.ts`, `useKeyboardShortcuts.ts`)
- Tests: Source name + `.test.ts` (e.g., `validation.test.ts`)

**Directories:**

- Lowercase plural (e.g., `components/`, `services/`, `hooks/`, `utils/`)
- Semantic grouping by concern (UI, business logic, reusable logic, utilities)

**Functions/Exports:**

- Components: PascalCase export (e.g., `export function App()`, `export function ComponentRow()`)
- Utilities: camelCase (e.g., `export function normalizeDescription()`, `export function escapeCSVValue()`)
- Event handlers: Suffixed with "Handler" type, named as `handle{Action}` in components (e.g., `handleGenerate`, `handleConfirm`)
- Hooks: Prefixed with "use" (e.g., `useKeyboardShortcuts`)

**Types:**

- Interfaces: PascalCase with suffix indicating type (e.g., `ComponentData`, `Settings`, `ComponentListProps`)
- Union types: PascalCase (e.g., `AIProvider = 'gemini' | 'claude' | 'chatgpt'`)
- Event types: Suffixed with "Handler" (e.g., `LoadComponentsHandler`, `ApplyDescriptionHandler`)

## Where to Add New Code

**New Feature (e.g., bulk rename, tag assignment):**
- Primary code: Add handler in `src/main.ts` for Figma API interaction, new event type in `src/types.ts`, new UI component in `src/components/` (e.g., `BulkRenameModal.tsx`), new utility if needed in `src/utils/`
- Tests: Add `.test.ts` colocated with implementation (e.g., `BulkRenameModal.test.ts` if testing component logic, or new test in `src/services/` if testing business logic)
- Example flow: User clicks button → emit event from component → main thread handles event → emit response → component receives and updates state

**New Component/Module (e.g., component hierarchy tree view):**
- Implementation: Create in `src/components/` with descriptive PascalCase name (e.g., `ComponentTree.tsx`)
- Props: Define interface (e.g., `ComponentTreeProps`) above component function
- State: If complex, consider extracting logic to custom hook in `src/hooks/`
- Imports: Use absolute paths if project has aliases configured, otherwise relative paths
- Integration: Import and render in parent (e.g., add to App.tsx), pass callbacks as props

**Utilities (e.g., deduplicate descriptions, batch transform):**
- Shared helpers: Add to `src/utils/` (new file or existing file if similar purpose)
- Pure functions: No side effects, no component/hook dependencies
- Exports: Named exports, not default
- Tests: Colocated `.test.ts` file with same name
- Usage: Import in components/services that need the utility

**Services (e.g., new AI provider, database integration):**
- Implementation: Add to `src/services/` with descriptive filename (e.g., `huggingface.ts` for new provider)
- Pattern: If provider-like, follow ai.ts structure with `generateWith{Provider}()` function and integrate into dispatcher
- Tests: Colocated `.test.ts`, mock fetch if calling external APIs
- Integration: Add provider to `AIProvider` union in types.ts, import and call from services as needed

**Hooks (e.g., component selection state, document modification tracking):**
- Location: `src/hooks/` with "use" prefix (e.g., `useComponentSelection.ts`)
- Pattern: Pure hook, no component rendering logic
- Tests: Colocated `.test.ts` with Preact testing utilities if available (currently not set up)
- Integration: Import in component, call at top level

- Purpose: Project tracking (GSD agent logs, conversation history, specification documents)
- Generated: Yes (by GSD and project workflows)
- Committed: Yes (checked into repo)
