# Provider Fallback Chain

## Priority
LOW

## Description
Allow configuration of fallback providers when the primary provider fails. If ChatGPT is down, automatically try Claude, then Gemini.

## User Story
As a designer, I want the plugin to try alternative AI providers when my primary choice fails so that I can keep working even when one service has issues.

## Acceptance Criteria
- [x] Settings allows ordering providers as primary, secondary, tertiary
- [x] On primary failure (after retries), automatically try next provider
- [x] User is notified which provider ultimately succeeded
- [x] Fallback only triggers for availability errors, not auth errors
- [x] Each provider in chain must have valid API key configured
- [x] Providers without keys are skipped in fallback chain

## Technical Notes
- Requires multiple API keys configured simultaneously
- Auth errors should not trigger fallback (wrong key won't work elsewhere)
- Rate limit errors could trigger fallback (different provider may have quota)
- UI needs to show which provider is currently being used
- Consider showing "Generated by [provider]" indicator

## Dependencies
- Requires retry logic (spec 011) to be implemented first

## Implementation Notes

- Created `src/services/fallback.ts` with:

  - `getProviderDisplayName(provider)` - Human-readable provider names
- Added `generateDescriptionWithFallback` in `src/services/ai.ts` that tries providers in order
